# 饲料供应链经营分析 Agent（Feed-Agent）

基于作品集 P1–P3（采购成本监测 / NIR 快检 / 旺季生产库存配送）的数据与业务背景，
构建的一个**可演示、可评测、可复现**的经营分析 Agent。
LLM 只负责理解问题和选工具，所有计算由确定性工具完成，SQL 由语义层拼接，不由大模型写。

## 快速开始

```bash
# 零依赖演示（无需任何 API key，仅 Python 标准库 + duckdb/pandas/pulp）
python app.py                # 打开 http://127.0.0.1:8611 （聊天页 + /eval 评测页）
python agent/agent.py "8月成都厂草鱼料的吨原料成本为什么比7月涨了？"   # 命令行模式
python eval/run_eval.py v0.3  # 跑 30 题评测
```

## 切换真实大模型（LLM 模式）

编辑 `config.yaml`：

```yaml
mode: llm
llm:
  api_key: "sk-xxxx"                       # 填入你的 key
  base_url: "https://api.moonshot.cn/v1"   # Kimi（月之暗面），OpenAI 兼容接口
  model: "kimi-k2-0905-preview"
```

DeepSeek / 通义千问等任何 OpenAI 兼容且支持函数调用的接口都可以，注释里有示例。
填入 key 后同一套 30 题评测脚本可直接用于 LLM 模式，也可跑基线A（LLM 裸写 SQL）对照实验。

## 架构

```
用户提问 → Agent 主循环（agent/agent.py，约200行自写函数调用编排）
  ├ llm 模式：OpenAI 兼容函数调用（理解、选工具、写解读）
  └ offline 模式：确定性规则路由（无 API 时演示与评测用）
→ 工具层（agent/tools.py，确定性计算）
  ├ list_metrics / query_metric   读 semantic/metrics.yaml 指标卡 → 拼 SQL → DuckDB
  ├ decompose_cost_change         吨成本三因素分解（价格/配方/出成率）
  ├ optimize_formula              PuLP 最低成本配方（影子价格、检验数）
  ├ run_readonly_sql              兜底只读 SQL（禁写关键字 + LIMIT 500 + JSONL 日志）
  └ search_docs                   简易 RAG：TF-IDF 字符 n-gram 检索 portfolio 文档
→ 数字溯源检查（程序校验：回答中每个数字必须能在工具返回或派生值池中找到来源）
→ 回答 + 来源（工具名、参数、SQL 可展开）
```

## 数据（data/company.duckdb，2024-01 ~ 2025-12）

虚构的一家饲料公司：3 个工厂（成都/眉山/绵阳）、4 个产品（草鱼料、鲈鱼膨化料、
育肥猪料、对虾料）、8 种原料、6 个供应商、约 200 个客户、6 个销售区域。
11 张表：5 张维度表 + 采购/质检批次/配方/生产工单/日库存/销售/期货月均价 7 张事实表。

原料采购价锚定**真实期货行情**（豆粕 M、菜粕 RM、玉米 C 主力月均价，来自 P1 项目抓取的
交易所数据）加随机基差；配方每月按当月价格用 LP 重算，随价格波动——与真实饲料企业运作一致。

**埋点**（data/buried_problems.json，6 个已知问题，作为归因题的标准答案）：

| 编号 | 埋点 | 真值 |
|---|---|---|
| BP1 | 成都厂 2025-08 草鱼料出成率异常 | 91.00%（邻月 95.8/96.5），当月玉米水分 15.38% |
| BP2 | S03 供应商 2025Q3 豆粕蛋白偏低 | 41.34%（其他供应商 42.8–43.1） |
| BP3 | 华东区域回款恶化 | 上半年 45.4 天 → 下半年 80.8 天，拐点 2025-07 |
| BP4 | 眉山厂 2025-03 价格高点集中采购豆粕 | 968.2 吨（月均 3 倍），当月偏离度 +1.9% |
| BP5 | 重庆 2025-09 OTIF 骤降 | 76.9%（邻月 90.9/94.7），旺季运力不足 |
| BP6 | 2025-07 鱼粉全年最高价 | 13,644 元/吨 |

真实数据没有标准答案，模拟数据有——这是做量化评测的前提。

## 语义层（semantic/metrics.yaml，10 个指标卡）

吨料原料成本、出成率、库存周转天数（needs_clarification，含原料·数量·日均 /
成品·金额·期初期末两个口径变体）、采购价对期货偏离度、单位蛋白成本、OTIF、
回款天数、质检蛋白均值、采购量、销售金额。
指标卡定义了公式、粒度、可筛选维度、口径注意事项——**口径是地基**：
库存周转天数原料口径月均约 1.0 天、成品口径月均约 13.4 天，不澄清口径直接回答就是错一半。

## 两个核心算法

**吨成本因素分解**（连环替代法）：C = Σ(r·p)/y，拆为价格效应 Σ r₀(p₁−p₀)/y₀ +
配方效应 Σ(r₁−r₀)p₁/y₀ + 出成率效应 Σr₁p₁(1/y₁−1/y₀)，三项和恒等于 C₁−C₀（已程序校验）。
面试追问点：结果受替代顺序影响；顺序无关的做法是 Shapley 分解（对每个因素在 3!=6
种顺序下的边际贡献取平均）。

**最低成本配方**：PuLP/CBC 线性规划，目标最小化吨成本，约束为营养标准
（蛋白/赖氨酸上下限等，参照《中国饲料成分及营养价值表》与水产饲料营养需要量公开资料设定），
输出新配方、吨成本、紧约束影子价格、检验数。配方输出一律标注"建议，需配方师确认"。

## Agent 规则与护栏

系统提示词五条铁律：①回答里的每个数字必须来自本轮工具返回；②指标不在目录或口径
多版本时先澄清；③每个结论附来源（工具名+参数）；④配方/采购类输出一律标"建议"；
⑤答不了时说明缺什么数据。

程序护栏（不靠提示词）：数据库只读连接、SQL 禁写关键字+行数上限+JSONL 日志、
数字溯源检查（从最终回答提取全部数字与工具输出逐一比对，容差 0.5%，对不上即标记）。
溯源检查在开发期真实抓到过 3 次问题（日期被误识别为数字、供应商编号误识别、
派生均值未登记），均已修复。

## 评测（eval/）

30 题（单指标 10 / 下钻环比 8 / 归因 5 / what-if 4 / 澄清 1 / 拒答 2），
判分：数值正确率（±0.5% 容差）、根因命中、澄清正确性、数字幻觉率（溯源通过率）、
耗时与工具调用数。迭代记录见 `eval/CHANGELOG.md`：

| 版本 | 准确率 | 溯源通过率 | 改动 |
|---|---|---|---|
| v0.1 | 96.7% | 100% | 首版 |
| v0.2 | 100% | 100% | 修月份区间解析（"7到9月"） |
| v0.3 | 100% | 100% | 增加"下半年/全年"解析；修口径变体单位显示 |

基线A（LLM 裸写 SQL，无语义层护栏）待配置 API key 后运行，结果留空不编造。
注意：offline 模式为确定性路由，100% 说明题库被规则覆盖，不代表泛化能力。

## 技术选型与理由

DuckDB（单文件、标准SQL、零运维）· 自写 YAML 语义层（透明，每步讲得清；对应了解
dbt MetricFlow / Cube）· PuLP+CBC（免费成熟）· 自写函数调用循环约 200 行（先不上
LangGraph，每步可解释）· Web 界面用 Python 标准库 http.server 而非 Streamlit
（本机 pip 装 Streamlit 多次超时；stdlib 方案零依赖、同样能提供聊天+SQL展开+评测页，
且少一个攻击面）· JSONL 日志做追踪。

对应规格文档 6 天计划：D1 数据+埋点 ✓（data/build_data.py，埋点 SQL 全部验证可查）；
D2 指标卡+手算核对 ✓；D3 分解恒等式+配方优化 ✓；D4 Agent 循环+演示问题 ✓；
D5 评测 v0.1→v0.3 ✓；D6 Web 界面+README ✓（录屏待自行补充）。
